# 커밋

변경 사항을 하나의 커밋으로 만든다. 메시지는 **한 줄**, 형식은 `라벨: 서브젝트`.

## 형식

```
라벨: 한글로 쓴 서브젝트
```

- 서브젝트는 **반드시 한글**. 코드 심볼, 파일명, 라이브러리명, 에러 문자열은 원문 그대로 둔다.
- 한 줄로 끝. scope 괄호(`feat(auth):`), 본문, 푸터, `Co-Authored-By` 전부 쓰지 않는다.
  사용자가 이 저장소에서 원하는 건 훑어보기 쉬운 한 줄짜리 로그다.
- 서브젝트 끝에 마침표 없음. 명사형(`~ 추가`, `~ 수정`)으로 끝낸다.
- 50자 내외. 길어지면 무엇을 왜 바꿨는지가 아니라 뭘 건드렸는지만 나열하고 있다는 신호다.

## 라벨

| 라벨 | 언제 |
|---|---|
| `feat` | 사용자가 쓸 수 있는 기능이 늘어남 |
| `fix` | 잘못 동작하던 것이 고쳐짐 |
| `style` | 화면에 보이는 모양/CSS만 변함, 동작 그대로 |
| `refactor` | 동작은 같고 코드 구조만 변함 |
| `docs` | 문서만 변함 |
| `test` | 테스트만 변함 |
| `chore` | 빌드 설정, 의존성, 스크립트 등 나머지 |

## 절차

1. `git status --short`와 `git diff HEAD`로 **실제로 무엇이 바뀌었는지** 읽는다.
   diff를 안 보고 쓴 메시지는 대체로 틀린다.
2. `git add -A`로 전부 스테이징한다.
   단, 실수로 들어온 것(`.env`, 빌드 산출물, 대용량 바이너리, 비밀키)이 보이면 add 전에 사용자에게 알린다.
3. 커밋한다. 변경이 여러 성격이어도 **커밋은 항상 하나**.
   라벨은 그 변경 묶음을 가장 잘 대표하는 것 하나를 고른다. 애매하면 사용자가 이번에 하려던 일이 무엇이었는지를 기준으로 고른다.
4. `git log --oneline -1`로 결과를 보여준다.

push는 하지 않는다. 사용자가 따로 요청하면 그때 한다.

## 예시

기능 추가:
```
feat: 갤러리 라이트박스 추가
```

버그 수정 — 코드 심볼은 원문 유지:
```
fix: WeddingDate 카운트다운이 자정에 하루 밀리는 문제 수정
```

여러 성격이 섞였을 때 — 컴포넌트 3개 스타일 + 오타 수정이 섞였지만 주된 작업은 스타일:
```
style: 초대장 카드 여백과 폰트 크기 정리
```

설정 변경:
```
chore: Next.js 15로 업그레이드
```

나쁜 예:
```
feat(gallery): add lightbox        ← 영어 서브젝트, scope 괄호
update files                       ← 라벨 없음, 내용 없음
fix: 버그 수정.                     ← 무엇을 고쳤는지 없음, 마침표
```
