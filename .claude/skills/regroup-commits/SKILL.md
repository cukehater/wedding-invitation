# 커밋 재그룹핑

여러 커밋을 의미 단위로 묶어 하나씩의 커밋으로 합친다. 히스토리를 다시 쓰는 작업이라 되돌리기가 번거롭기 때문에, **계획을 먼저 보여주고 승인을 받은 뒤에만** 실행한다.

## 1. 범위 확정

기본 범위는 없다. 사용자가 말한 범위를 그대로 쓴다.

- "최근 5개" → `HEAD~5..HEAD`
- "a7c5b7b부터" → `a7c5b7b^..HEAD` (그 커밋 자신도 포함)
- "푸시 안 한 것 전부" → `@{upstream}..HEAD`
- 범위를 말하지 않았다면 `git log --oneline @{upstream}..HEAD`를 보여주고 어디까지 묶을지 물어본다. 추측해서 진행하지 않는다.

확정한 범위의 가장 오래된 커밋의 **부모**가 rebase base다. 이 base는 이후 모든 명령에서 쓰인다.

## 2. 실행 전 점검

세 가지를 확인하고, 문제가 있으면 멈추고 사용자에게 알린다.

- `git status --porcelain`이 비어 있는가. 작업 트리가 더러우면 rebase가 실패한다. 커밋하거나 stash할지 물어본다.
- 범위에 이미 푸시된 커밋이 있는가. `git log --oneline <base>..@{upstream}`에 뭔가 나오면 force push가 필요하다는 뜻이므로, 공유 브랜치라면 위험하다고 먼저 경고한다.
- `git rev-parse HEAD`를 기록해 둔다. 실패했을 때 `git reset --hard <그 sha>`로 원상복구할 수 있고, 계획을 보여줄 때 이 sha를 함께 알려주면 사용자가 안심한다.

## 3. 그룹 나누기

`git log --oneline <base>..HEAD`와 필요하면 `git show --stat <sha>`로 각 커밋이 실제로 무엇을 건드렸는지 읽는다. 메시지만 보고 묶으면 대체로 틀린다.

묶는 기준은 **"나중에 이 로그를 훑는 사람이 하나의 사건으로 이해할 단위"**다.

- 같은 기능을 여러 번에 걸쳐 만든 커밋들 → 하나로. (`방명록 API 추가` + `방명록 UI 연동` + `방명록 오타 수정`)
- 바로 뒤에 온 자기 수정·오타·리뷰 반영 커밋 → 앞 커밋에 흡수.
- 성격이 다르면 억지로 합치지 않는다. 기능 추가와 무관한 의존성 업그레이드는 따로 남긴다.
- 그룹은 **1개짜리도 괜찮다**. 이미 잘 쪼개진 커밋을 굳이 건드리지 않는 것도 정리다.
- 순서는 가능한 한 원래 순서를 지킨다. 떨어져 있는 커밋을 끌어와 묶으면 충돌 확률이 올라간다. 꼭 필요할 때만 재배치하고, 그 사실을 계획에 적는다.

그룹 메시지는 이 저장소의 커밋 컨벤션을 따른다: 한 줄, `라벨: 한글 서브젝트`, 마침표 없음, 명사형 종결, 50자 내외. 라벨은 `feat` `fix` `style` `refactor` `docs` `test` `chore` 중 그룹을 가장 잘 대표하는 하나. 자세한 규칙은 `commit` 스킬과 동일하다.

## 4. 계획 제시

이 형태로 보여주고 승인을 기다린다. 승인 없이 rebase를 실행하지 않는다.

```
base: 7f559c0 (이 커밋은 그대로 유지)
복구용: git reset --hard 1d35bcb

1) feat: 방명록 CRUD 구현
   9c2eb2e chore: Neon Postgres 연결과 방명록 스키마 추가
   e720b0c feat: 방명록 비밀번호 해싱과 입력 검증 로직 추가
   55e4198 feat: 방명록 목록·등록·삭제 API 추가
   fd97552 feat: 방명록을 API 연동으로 교체하고 삭제 시 비밀번호 확인 추가

2) chore: 인앱 브라우저 진단용 debug 프로브 추가
   bb32a2e (그대로)

18개 → 6개
```

문서·플랜 커밋처럼 사용자가 남기고 싶어할 수도 있는 것을 흡수하려 한다면 그 점을 한 줄로 짚어준다.

## 5. 실행

rebase todo를 직접 만들어 넣는다. `fixup`은 편집기를 열지 않고, `exec ... --amend -m`으로 그룹 메시지를 박으므로 대화형 편집기가 전혀 뜨지 않는다.

todo 파일을 스크래치패드에 쓴다. 그룹마다: 첫 커밋은 `pick`, 나머지는 `fixup`, 마지막에 `exec`로 메시지 교체. 1개짜리 그룹도 메시지를 바꿀 거면 `exec`를 붙이고, 그대로 둘 거면 `pick`만 쓴다.

```
pick 9c2eb2e
fixup e720b0c
fixup 55e4198
fixup fd97552
exec git commit --amend -m "feat: 방명록 CRUD 구현"
pick bb32a2e
```

그리고:

```bash
GIT_SEQUENCE_EDITOR="cp $TODO" git rebase -i <base>
```

`GIT_SEQUENCE_EDITOR`는 `<명령> <todo경로>` 형태로 호출되므로 `cp $TODO`가 그대로 todo를 덮어쓴다.

충돌이 나면 **직접 해결하려 들지 말고** `git rebase --abort`로 되돌린 뒤, 어느 커밋에서 충돌했는지와 그룹 순서를 바꾼 것이 원인인지 사용자에게 보고한다. 재배치 없이 다시 묶는 안을 제시한다.

## 6. 결과 확인

`git log --oneline <base>..HEAD`로 결과를 보여준다. `git diff <기록해둔 원래 HEAD> HEAD`가 **비어 있어야 한다** — 합치기는 내용을 바꾸지 않는 작업이므로, 여기서 뭔가 나오면 잘못된 것이고 즉시 알려야 한다.

push는 하지 않는다. force push가 필요하다면 `git push --force-with-lease`가 필요하다고만 알리고, 실행은 사용자가 따로 요청할 때 한다.
